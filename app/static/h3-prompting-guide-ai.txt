MiniMax H3 Prompting Guide for AI Agents
AI Video Site V2 / OpenFunRus/aivideosite
Version: 2026-11-20-canonical-fields

PURPOSE
=======

This is the authoritative prompt-writing guide for the local AI Video Site V2.
It is tailored to the site's real ComfyUI-MiniMaxH3-Easy pipeline, not to Mage's UI.

Prompting principles were cross-checked against the public MiniMax-H3 prompting guide at:
https://www.mage.space/ru/models/minimax-h3/prompting-guide

IMPORTANT: Mage terminology is used only where it describes MiniMax-H3 behavior.
The LOCAL SITE behavior, limits, media ordering and server wrapping described below take priority.

======================================================================
1. THE MOST IMPORTANT RULE FOR THIS SITE
======================================================================

For ordinary V2 prompt fields and Magic Wand output, write THREE fields in this exact order:

integrated_multimodal_description: ...

overall_soundscape: ...

non_diegetic_music: ...

Leave one blank line between fields.

WHY THIS SITE USES THREE FIELDS EVERYWHERE
------------------------------------------

FRAMES / FL2VA can consume this format directly.

REFERENCES / Characters / Continue / Audio / Continue Clip use Ref2VA internally.
The server owns the real attached-reference mapping. When it receives the canonical three-field prompt,
it safely promotes it to the six-field Ref2VA format:

subject_definitions
summary
retention_analysis
detailed_description
overall_soundscape
non_diegetic_music

The server inserts the real <Picture N>, <Video N>, <Audio N> and Character mappings.

Therefore:
- Magic Wand MUST NOT invent Picture/Video/Audio ordinals.
- Magic Wand MUST NOT invent subject_definitions or retention_analysis for normal V2 use.
- Do not nest three labeled fields inside detailed_description manually.
- Only write a fully explicit six-field Ref2VA prompt if the user explicitly asks for low-level output
  and the actual reference map is known.

======================================================================
2. LANGUAGE RULE
======================================================================

Production H3 instructions are written in ENGLISH:
- field names;
- scene description;
- camera;
- lighting;
- actions;
- soundscape;
- music direction;
- exclusions;
- continuity instructions.

Keep literal content in its intended language:
- exact spoken dialogue;
- exact lyrics;
- exact visible text.

Dialogue example:
A tired man (S1) with a low, rough voice says:
<d>[Russian] Я уже пришёл.</d>

Do not translate exact dialogue unless the user explicitly asks.

======================================================================
3. SHOTS AND TIMING
======================================================================

[Shot 1] has NO timestamp.

Every later cut has an exact increasing time:
[Shot 2] At 00:04.000, the camera cuts to...

The timeline must fit the selected generation length.
The final shot naturally continues until the end.

Good planning for the simplified V2 durations:
- 5 sec: usually one clear shot, sometimes two simple shots.
- 10 sec: usually one continuous action or two clearly separated shots.
- 15 sec: two or three shots are practical when the story truly needs cuts.

These are recommendations, not hard model limits.

Every cut should add a meaningful change:
- new viewpoint;
- new location;
- new subject;
- new state;
- meaningful time jump.

Do not cut just to make the same action slightly closer.
Use camera movement instead when continuity is better.

For one continuous take:
[Shot 1] ... in one continuous shot with no cuts.

Do NOT combine "one continuous shot" with [Shot 2], [Shot 3], etc.

======================================================================
4. HOW TO WRITE EACH SHOT
======================================================================

A strong shot normally contains, in this order:

1. style and framing;
2. visible subject + location + starting state;
3. one primary camera behavior;
4. action in chronological order;
5. visible final state;
6. action-linked sound when relevant.

Example structure:

[Shot 1] Live-action, cinematic, a medium shot frames a man beside a rain-soaked bus stop at night.
The camera pushes in with small amplitude at slow speed.
He looks down at the ticket in his right hand, folds it once, raises his eyes toward the arriving bus,
then takes one step forward. Water splashes under his boot.

Prefer concrete details:
- shallow depth of field;
- sodium streetlight from camera-left;
- wet pavement reflecting magenta signage;
- right hand stays on the railing;
- feet remain planted;
- turns 90 degrees toward screen-right.

Avoid empty praise:
- beautiful;
- amazing;
- epic;
- cinematic masterpiece.

"Live-action, cinematic" is useful as a style label, but the actual visual direction should be concrete.

======================================================================
5. CAMERA VOCABULARY
======================================================================

Use camera movements as sentences, not a keyword pile.

static shot
- camera does not move.

push in / pull out
- physical camera moves closer / farther.

zoom in / zoom out
- lens changes while camera position stays fixed.

pan left / pan right
- camera rotates horizontally in place.

truck left / truck right
- camera physically slides sideways.

tilt up / tilt down
- camera rotates vertically in place.

pedestal up / pedestal down
- entire camera rises / lowers.

arc shot
- camera moves on an arc around subject.

tracking shot
- camera travels with a moving subject.

POV
- view through a character's eyes.

roll clockwise / roll counterclockwise
- frame rotates around lens axis.

shake slightly / shake strongly
- deliberate handheld/impact shake.

Useful modifiers:
with small amplitude at slow speed
with large amplitude at fast speed

RULE:
Use one primary camera behavior per shot unless the user explicitly wants complex choreography.

======================================================================
6. SOUND — THREE DIFFERENT LAYERS
======================================================================

A. ACTION-LINKED SOUND
Write it inside integrated_multimodal_description next to the action:
- the glass taps the table;
- boots scrape on gravel;
- the door latch clicks.

B. OVERALL AMBIENCE
Write in overall_soundscape:
- rain;
- wind;
- room tone;
- crowd;
- traffic;
- machinery;
- breathing/laughter that persists through the clip.

C. AUDIENCE-ONLY SCORE
Write only in non_diegetic_music.

If no generated score is wanted:
non_diegetic_music: N/A

Do not write vague score instructions like:
epic emotional uplifting music

Prefer:
Low cello pulses at a slow tempo, sparse percussion every two beats, gradually increasing in volume.

If the whole clip should have no generated ambient/physical audio:
overall_soundscape: N/A

======================================================================
7. DIALOGUE, VOICE AND LYRICS
======================================================================

Give each speaking voice a stable ID:
(S1), (S2), etc.

Describe a voice once:
age range, gender presentation if relevant, pitch, timbre, pace, accent, on-screen/off-screen.

Exact spoken line:
<d>[Russian] Не подходи ближе.</d>

Do not translate it.
Do not repeat dialogue in overall_soundscape or non_diegetic_music.

Fit dialogue into the actual shot time.
A long paragraph cannot be lip-synced inside a 2-second shot.

For narration:
A calm older woman (S1) says in an off-screen voiceover:
<d>[Russian] Дорога заканчивается у старого моста.</d>

If the visible person must NOT lip-sync to voiceover:
say that their lips remain closed.

Never invent lyrics for the Audio workspace if the user did not provide them.

======================================================================
8. ON-SCREEN TEXT AND EXCLUSIONS
======================================================================

If exact visible text matters, quote it exactly:
A red warning sign reads "ВХОД ЗАПРЕЩЁН".

Keep visible text limited and simple.
Do not put important text across faces.

MiniMax-H3 does not use a separate negative-prompt field in this V2 workflow.
Write concrete exclusions as normal sentences, e.g.:

No subtitles, on-screen text, logos, or watermarks.
No extra people enter the frame.
The character never changes clothes.

Do not fill the prompt with generic negative-prompt spam.

======================================================================
9. CREATE WORKSPACE — TEXT / FIRST / LAST
======================================================================

Visible normal V2 choices:
- Quality: 480p / 720p / 1080p
- Ratio: 1:1 / 16:9 / 9:16
- Duration: 5 / 10 / 15 sec
- Steps: 8 / 12 / 16
- Seed
- H3 generated sound on/off

A) TEXT ONLY
Use the normal three fields.

Example:

integrated_multimodal_description: [Shot 1] Live-action, cinematic, a medium-wide shot frames a tired traveler standing beneath a flickering station light at night, holding a small canvas bag in his left hand. The camera slowly pushes in. He hears a train approaching, turns his head toward screen-left, tightens his grip on the bag, and takes one deliberate step toward the platform edge.

overall_soundscape: Distant rail noise grows louder, cold wind moves through the empty station, and the overhead light hums softly.

non_diegetic_music: N/A

B) FIRST FRAME ONLY
Prepend this exact functional alignment line:

For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

Then blank line + the three fields.

Start from the visible image state.
Do not waste prompt space re-describing every obvious still detail.
Describe the FIRST visible motion after frame zero.

C) FIRST + LAST FRAME
Prepend:

How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.

Replace:
- N with the final shot number;
- S.SS with exact selected duration, e.g. 10.00.

Prefer one continuous physical transition unless a cut is genuinely needed.
Explicitly converge into the final frame state.

D) LAST FRAME ONLY
Use the matching last-frame alignment syntax and describe a plausible path into the final image.

LOCAL V2 COMBINATION RULE:
- first/last without Characters -> FL2VA exact endpoint anchors.
- Characters without first/last -> Ref2VA identity/voice references.
- Characters + first/last -> Ref2VA plus native MiniMaxH3AddGuide exact timeline anchors.
- In mixed mode, do not invent <Picture N> alignment labels for guide images: the backend attaches First/Last separately from Character reference numbering.

======================================================================
10. CHARACTERS / REFERENCES — WHAT MATTERS HERE
======================================================================

The reusable Character selector can provide:
- 1–4 appearance images;
- description/identity notes;
- optional saved voice.

For normal V2 use:
- refer to the person naturally in the three-field scene prompt;
- keep identity/clothes/props invariant;
- do NOT guess <Picture N> numbering.

The backend creates the six-field Ref2VA wrapper and real labels.

Reference retention concepts used internally:
- fully_preserved: exact identity/product/logo-like traits.
- partially_preserved: keep stated parts, allow other change.
- attribute_transfer: copy a selected property/style/texture.
- weak_reference: loose visual guidance.

Audio concepts:
- fully_copy;
- partially_copy;
- reference;
- weak_reference.

Face consistency requires an attached Character/image reference.
Text description alone is not a reliable identity lock.

======================================================================
11. CONTINUE WORKSPACE
======================================================================

This is Ref2VA video continuation internally.
The previous/source video is attached by the site.

Prompt only the NEXT visible segment.

The first shot must continue the source END STATE:
- same identity;
- same outfit;
- same props;
- same body orientation;
- same screen direction;
- same movement momentum;
- same camera height/direction/motion;
- same lighting direction;
- same scene geography.

Avoid:
- restarting the action;
- teleporting;
- reversing direction without cause;
- resetting arms/legs/props;
- suddenly changing lens/camera side.

Good 10-second example:

integrated_multimodal_description: [Shot 1] Live-action, cinematic, continuing directly from the source video's final frame, the man keeps walking toward the metal door without breaking stride. The camera continues the same slow forward tracking motion. He takes two more steps, reaches the handle with his right hand, pushes the door inward, and pauses in the doorway while still facing screen-right. [Shot 2] At 00:06.000, the camera cuts to a medium shot from inside the same room as he steps across the threshold and looks toward the dim corridor ahead.

overall_soundscape: His footsteps continue at the same pace, the metal handle clicks, the door hinges creak, and the room tone remains quiet and enclosed.

non_diegetic_music: N/A

The backend supplies the real video-reference labels and Ref2VA wrapper.

======================================================================
12. AUDIO WORKSPACE
======================================================================

Purpose:
audio-driven performance / singing / dancing using a selected MASTER TRACK fragment.

The selected track fragment is the driving audio input.
The user separately chooses:
- "Вклеить трек в видео" / embed_track
- "Фоновые звуки H3" / generate_scene_audio

CRITICAL:
The master track is NOT music H3 should invent.
Therefore normal Audio prompts use:

non_diegetic_music: N/A

If generate_scene_audio is OFF:
overall_soundscape: N/A

If generate_scene_audio is ON:
overall_soundscape contains only additional scene sounds:
- stage footsteps;
- cloth movement;
- crowd ambience;
- room reverb;
- physical impacts.

Do NOT describe the master song again in overall_soundscape.

Describe visible performance:
- mouth articulation if singing is requested;
- gaze;
- torso/arm motion;
- feet planted vs stepping;
- gesture accents;
- camera;
- physical interaction with microphone/instrument.

Do not invent lyrics.

Example:

integrated_multimodal_description: [Shot 1] Live-action, cinematic, a medium close-up frames the performer facing the camera as the supplied driving audio plays. She sings with natural mouth articulation synchronized to the provided track, keeps both feet planted, gently shifts her shoulders to the rhythm, and raises her left hand once at chest height. The camera pushes in with small amplitude at slow speed. [Shot 2] At 00:06.000, the camera cuts to a close-up as she keeps singing, lowers her hand, and holds eye contact with the lens through the end of the segment.

overall_soundscape: N/A

non_diegetic_music: N/A

======================================================================
13. CONTINUE CLIP WORKSPACE
======================================================================

Purpose:
create the next segment of the same music-video sequence.

Inputs already known by the site:
- previous generated clip;
- same master track;
- next track time range;
- selected Characters/references.

Treat the master track exactly like Audio:
non_diegetic_music: N/A

If H3 scene sounds are OFF:
overall_soundscape: N/A

Continue from previous clip END STATE.
Prompt only the next action.

Example:

integrated_multimodal_description: [Shot 1] Live-action, cinematic, continuing directly from the previous segment's final frame, the performer keeps both feet planted and continues the same torso rhythm. The camera maintains the existing slow tracking direction. He turns his shoulders slightly toward screen-right, raises his left hand in one smooth gesture, then lowers it while keeping his head aligned with the beat. [Shot 2] At 00:07.000, the camera cuts to a tighter medium shot as he leans back a few centimeters, returns upright, and finishes the segment looking directly into the lens.

overall_soundscape: N/A

non_diegetic_music: N/A

======================================================================
15. COMMON FAILURE MODES
======================================================================

BAD: loose plot summary
"They fall in love and it is dramatic."

GOOD:
Describe visible behavior shot by shot.

BAD: contradictory camera
"one continuous take" + [Shot 2] camera cuts to...

GOOD:
Choose one.

BAD: more shot time than selected duration.

GOOD:
All cut times are inside the selected 5/10/15 sec window.

BAD:
non_diegetic_music: epic emotional uplifting

GOOD:
non_diegetic_music: Sparse low strings at a slow tempo, one sustained chord, gradually rising in volume.

BAD:
long speech inside a short shot.

GOOD:
short exact line that fits.

BAD:
assume a face stays consistent from text alone.

GOOD:
attach a Character/image.

BAD:
in Audio mode ask H3 to create the same master song again.

GOOD:
master track is external/driving; non_diegetic_music: N/A.

BAD:
invent <Picture 1>/<Audio 2> numbers in Magic Wand output.

GOOD:
write the canonical three fields; let backend map references.

======================================================================
16. SETTINGS POLICY FOR OUR V2
======================================================================

Do not silently change form settings during prompt improvement.

Default visible options:
Quality: 480 / 720 / 1080
Ratio: 1:1 / 16:9 / 9:16
Duration: 5 / 10 / 15 sec
Steps: 8 / 12 / 16
Seed: automatic when empty

Prompt timing MUST follow the selected duration.

Steps:
- 8: fast/turbo-style straightforward work where supported.
- 12: balanced default.
- 16: more compute; not automatically better for every scene.

Do not claim higher resolution/steps guarantee better motion or identity.

======================================================================
17. MAGIC WAND OUTPUT CONTRACT
======================================================================

For V2 prompt improvement:
- preserve user intent;
- do not change settings;
- output changes.prompt only;
- use canonical three fields;
- use English instructions;
- preserve exact literal dialogue/lyrics/on-screen text;
- exact shot timing for selected duration;
- one primary camera behavior per shot;
- no invented media/reference labels;
- no invented dialogue/lyrics;
- no invented music unless requested;
- Audio/Continue Clip master track -> non_diegetic_music: N/A;
- sound disabled -> overall_soundscape: N/A;
- if first/last frames are present in Create, prepend the correct alignment line.

======================================================================
18. QUICK CHECKLIST BEFORE RETURNING A PROMPT
======================================================================

Check:
[ ] three fields are present and ordered correctly;
[ ] [Shot 1] has no time;
[ ] later cuts use exact increasing times;
[ ] all actions fit selected duration;
[ ] one main camera move per shot;
[ ] actions are observable and chronological;
[ ] final state is clear when continuity matters;
[ ] dialogue has stable speaker ID + <d>[Language] exact text</d>;
[ ] action sounds / ambience / score are not mixed together;
[ ] no unwanted music: non_diegetic_music: N/A;
[ ] Audio/Clip did not invent the master track again;
[ ] no fake reference ordinals;
[ ] identity/props/handedness/screen direction are stable;
[ ] no contradictions such as continuous take + cuts.
