# V2 — единый дизайн генераторов

Статус: базовый визуальный контракт для вкладок **Создать**, **Продолжить**, **По аудио**, **Продолжить клип**. При разработке следующих генераторов сначала используйте эти компоненты; различия допускаются только для специфичного содержимого вкладки.

## Общий каркас

- Один page title в `layout/topbar.html`, без повторного заголовка внутри формы.
- Под ним короткое пояснение (`.v2-workspace-intro`), затем prompt, медиа/референс, настройки, основная кнопка.
- `.v2-generator-form`: единая ширина и **14px** между последовательными блоками. Не добавлять одновременно `gap` формы и `margin-top` карточкам.
- `.v2-tool-card` — единая оболочка карточек; prompt использует `.v2-prompt-panel`, счётчик справа, wand в поле и помощь снизу.
- Заголовки секций: **14px**, насыщенность **750**, иконка в квадратном фиолетовом бейдже **42×42px** (`.v2-heading-icon`). Для prompt — wand, для визуального источника — photo/video, для музыки — music.
- Вторичная подсказка под названием медиа-карточки — компактный приглушённый текст; не смешивать с заголовком страницы.

## Источники файлов

- Для `Из библиотеки` / `Загрузить файл` использовать `.v2-source-actions`: две **раздельные** кнопки одинаковой ширины с **8px** промежутком, скругление каждой **10px**, активное состояние фиолетовое.
- Кнопки всегда занимают всю ширину карточки; медиаселектор и выбранный preview остаются специфичны для вкладки.
- Обёртка выпадающего выбора (`.v2-continue-source-picker` / `.v2-audio-source-picker`) имеет 10px padding, фон `#10131c`, скругление 11px, а `select` — высоту 42px. Стили должны совпадать.
- В заголовке «Исходный ролик» правило вертикальной раскладки применяется только к тексту, **не** к `.v2-heading-icon`, иначе SVG смещается внутри бейджа.
- Не менять `id` / `data-*-source-mode` и обработчики без необходимости.

## Панель настроек

- `.v2-generator-settings` — общий контейнер; `.v2-generator-settings-primary` для четырёх колонок и `.v2-generator-settings-secondary` для Seed, звука и запуска.
- `.v2-generator-setting` + `.v2-setting-label` — подписи **12px**, с тематической иконкой **16px**: adjustments (качество), photo (формат), clock (длительность), bolt (шаги).
- `.v2-segmented` — эталон из «Создать»: тёмный фон, 4px внутренний отступ, 5px между вариантами, кнопки минимум **34px** и шрифт **12px**, активный вариант градиентный фиолетовый.
- Create исторически использует `.v2-settings-card` и `.v2-setting-group`; общие правила применяются к ним без изменения работающего JS. Continue и Audio сохраняют `data-v2-setting` и специфичные контейнеры для поведения.
- До 1180px настройки переходят на две колонки, до 820px — на одну. Выбор библиотеки/загрузки сохраняет две колонки пока это помещается.
- `Вклеить трек` и `Фоновые звуки H3` существуют только в Audio; общая визуальная система не должна смешивать их логику с `Генерировать звук` других генераторов.
- `Продолжить клип` использует те же **Качество / Формат / Длительность / Шаги / Seed**, что другие генераторы. Звук управляется отдельными **«Вклеить трек в видео»** (ON) и **«Фоновые звуки H3»** (OFF), как во вкладке «По аудио».

## Где править

- **Общие визуальные правила этих генераторов:** `app/static/v2/css/workspaces/generator-design.css`, подключён после CSS конкретных вкладок.
- **Уникальная механика / разметка:** `views/{create,continue,audio}.html`, `css/create.css`, `css/workspaces/{continue,audio}.css`, JS соответствующей вкладки.
- **Продолжить клип:** `views/clip.html`, `css/workspaces/clip.css`, обработчики в `js/workspaces/generators.js`; сохранены `track_id`, `audio_start`, автоподстановка из Library → «След. клип».
- В «Продолжить клип» карточки предыдущего ролика и аудиодорожки идут **одна под другой на всю ширину**. Иконки в двух кнопках выбора источника — строго **17×17px**, выровнены по центру, как в других генераторах.
- Master track во вкладке «Продолжить клип» использует waveform с одним перетаскиваемым выделением вместо стандартного браузерного `<audio controls>`. Длина выделения задаётся нижними кнопками длительности; следующий `audio_start` после генерации увеличивается на номинальные 5/10/15 сек, а FFmpeg сегмент получает +1 сек запаса для итоговой дорожки.
- Не заводить новый вид сегментированных кнопок или source tabs внутри конкретной вкладки. При расширении дизайна сначала обновить общие правила и этот документ.

Визуальное утверждение выполняет пользователь на рабочем сервере (desktop/mobile). Статическая проверка файлов не заменяет браузерную.

## Библиотека

- В desktop строго **3 колонки** одинаковых карточек; неполный последний ряд не растягивать. На узких экранах 2/1 колонка.
- Превью **16:9** с бейджем длительности, затем название, компактные метаданные и единый ряд действий.
- «Открыть» — маленькая вертикальная иконка с подписью и синей подсветкой; «Скачать», «Продолжить», «След. клип» — такого же размера без выделения.
- После «След. клип» стоит сразу красная кнопка «Удалить». Меню `•••` и действие «Монтаж» в библиотеке не используются.
- Нижний ряд действий состоит ровно из **5 равных колонок** (`repeat(5,minmax(0,1fr))`), включая красную «Удалить»; иконки и подписи центрированы одинаково.
- Карточки при наведении не сдвигаются и не меняют рамку; расположение статично.
- Вверху только поиск по названию, «Обновить» и количество роликов. Фильтров по типу и сортировки нет.
- Поле поиска растягивается на всё свободное место до правых кнопок; «Обновить» и счётчик одинаковы по ширине (132px), высоте (44px) и размеру шрифта (12px).
- Пагинация **20 роликов на страницу**, центрированная внизу; при одной странице не показывается. Поиск сбрасывает номер текущей страницы.
- Пустая карточка состояния отображается только при полном отсутствии элементов либо отсутствии совпадений по поиску — никогда параллельно существующей сетке.

## Очередь

- Две равные панели GPU содержат название, VRAM, загрузку, температуру, тонкую полосу утилизации и состояние «Занята / Свободна».
- У занятой GPU в нижней строке указываются **только пользователь и время генерации**; не дублировать промпт задачи.
- Ниже заголовок «Задачи» и компактные строки с названием, статусом, процентом и полосой прогресса, временем и действиями. Существующие Stop / Retry / Result / Delete доступны по состоянию задачи.
- Зелёное «Готово», фиолетовое «В работе», нейтральное «В очереди», красное «Ошибка».
- Серверная пагинация **по 20 задач**, через `jobs_page` у `/api/v2/state`; показывается только если страниц больше одной. Пустое состояние скрыто при наличии задач.

## Чат

- **Логика:** это отдельный conversational endpoint `/api/assistant/chat`, а не Magic Wand и не form-control. Чат отвечает, обсуждает идеи, объясняет и советует; он не должен утверждать, что поменял форму, выбрал файл/Character или запустил задачу. Production-ready H3 prompt он пишет только когда пользователь явно просит prompt.
- Magic Wand всех генераторов работает через `/api/assistant/control` и получает **только состояние своего workspace**. Нельзя подмешивать draft/settings из «Создать» в Continue/Audio/Clip.
- Эталон — утверждённый макет с полноценными строками сообщений: assistant слева, user справа, рядом отдельные квадратные аватары **38×38px**.
- Вверху после пояснения компактный переключатель **Thinking** с маленьким toggle-switch и отдельная кнопка «+ Новый чат», обе высотой **38px**. Не заменять Thinking на широкую кнопку «Режим размышления».
- Счётчик активного контекста остаётся сразу под шапкой; история сообщений занимает оставшуюся высоту и прокручивается независимо от composer.
- Сообщение состоит из row → avatar + bubble. Пользователь — приглушённый фиолетовый справа, модель — тёмно-синяя карточка слева. Для новых сообщений сохраняется время и отображается внутри bubble; старой истории без timestamp выдуманное время не добавляется.
- После последнего успешного ответа модели показывается компактный status-row «Готов ответить.» с check-иконкой, как в утверждённом макете.
- Внизу textarea на всю доступную ширину и справа квадратная **54×54px** фиолетовая кнопка с иконкой бумажного самолётика, **без текста**. На узких экранах она остаётся квадратной **50×50px**.
- **Enter** отправляет сообщение, **Shift+Enter** вставляет новую строку. Пока запрос выполняется, отправка заблокирована; streaming, Thinking, очистка истории и счётчик контекста сохраняют прежнюю механику.
- В model API передаются только поля `role/content`; UI timestamp хранится локально и не попадает в контекст модели.
- Правила раздела: `views/chat.html`, `css/workspaces/chat.css`, `js/workspaces/chat.js`. Не копировать стили чата в общие компоненты генераторов.

## Система

- Эталон — утверждённый dashboard: **3 карточки в ряд** на desktop. Верхний ряд: RTX 3090, RTX 2080 Ti, Local Qwen3-8B. Второй ряд: ComfyUI, RAM / CPU, Диск.
- GPU-карточки показывают реальную загрузку GPU кольцом, VRAM полосой, температуру и текущего пользователя. Не дублировать промпт задачи.
- Qwen показывает target, состояние процесса, 32k context и reserved GPU; ComfyUI — состояние primary/secondary и общие queued/running.
- RAM / CPU и Disk используют кольцевые индикаторы и реальные значения API. Для CPU backend отдаёт `cpu_utilization`, вычисленный по дельте `/proc/stat`; load average остаётся отдельной справочной метрикой.
- Внизу три графика: GPU 0/1, RAM и CPU. История хранится только на клиенте за последние **10 минут** и строится исключительно из реально полученных snapshot — исторические значения не выдумываются.
- Вверху «Обновить», toggle «Автообновление» и интервал **5 / 10 / 15 / 30 сек**. По умолчанию автообновление включено на 5 секунд; выбранные настройки сохраняются локально для пользователя.
- Когда открыт workspace «Система», его polling управляется `system.js`; общий 4-секундный polling `bootstrap.js` оставлен только для «Очереди», чтобы не делать двойные запросы.
- До 1280px dashboard переходит на 2 колонки, до 900px — на одну. Графики следуют той же сетке.
- Правила раздела: `views/system.html`, `css/workspaces/system.css`, `js/workspaces/system.js`; CPU metric добавляется в `app/main.py`.

## Монтаж

- Эталон — утверждённый профессиональный layout: библиотека слева, большой viewer по центру, inspector справа, toolbar и timeline во всю ширину ниже.
- Текущий backend честно поддерживает **одну последовательную видеодорожку V1 + одну Music-дорожку**. Не рисовать рабочие V2/A1/A2 до расширения FFmpeg export.
- Библиотека имеет поиск, реальные preview через `/media/{id}`, выбор элемента и «Добавить»; двойной клик также добавляет ролик.
- Viewer использует собственный transport: предыдущий/следующий клип, ±1 сек, play/pause, project scrub и громкость preview. Позиция считается относительно всего последовательного проекта.
- Timeline имеет ruler, playhead, **pointer drag-reorder** клипов (не HTML5 `draggable`, потому что внутри клипа есть `<video>`), Snap 0.5s и zoom 8–32 px/s. Клип не должен выделять текст/preview при захвате. Длина каждого клипа на шкале соответствует его реальной effective duration.
- Inspector содержит вкладки «Клип / Аудио / Инфо». В «Клип» остаются только реально экспортируемые параметры: trim start/duration, split, volume, fade in/out. В «Аудио» — Music file, offset, trim, length, volume.
- Toolbar: selection, split, delete, undo/redo, snap, zoom. У выбранного клипа также появляется компактная красная корзина. Удаление должно работать кнопкой toolbar, корзиной на клипе и клавишами Delete/Backspace. Горячие клавиши: Space play/pause, Delete/Backspace удаление, Ctrl/Cmd+Z undo, Ctrl/Cmd+Y или Cmd/Ctrl+Shift+Z redo.
- Проект автоматически хранится per-user в localStorage. «Сохранить» выгружает JSON, «Открыть» импортирует JSON. Бинарный Music-файл в JSON не встраивается и после перезагрузки/импорта выбирается заново.
- Экспорт сохраняет существующий контракт `POST /api/editor/export`: последовательные clips + optional Music file. UI не должен обещать compositing, overlays или несколько независимых audio/video lanes, пока backend этого не поддерживает.
- Основные файлы: `views/editor.html`, `css/workspaces/editor.css`, `js/workspaces/editor.js`.


## Characters / правая панель

- На desktop правая панель постоянная и шире старой: **300px** (на 821–1100px — 270px). На mobile остаётся drawer.
- В шапке панели всегда доступна кнопка **«Добавить»**.
- Добавление идёт через V2 modal без перехода в V1: имя, описание, **1–4 изображения**, optional voice. Изображения можно выбирать несколькими подходами; новый выбор дополняет текущий набор до лимита 4.
- После успешного создания список обновляется. Новый Character автоматически выбирается только если это не нарушает H3 reference budget.
- Карточки остаются селекторами Characters; поиск, Все / Выбранные / Недавние и счётчик сохраняются.
